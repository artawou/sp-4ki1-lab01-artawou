# ЛР1 — «Ізоляційна Капсула»

Матеріал роботи: **https://docs.sp.ordynski.com/labs/lab01/story.html**
Формальний опис, порядок виконання й контрольні питання: там само, вкладка «академічна».

Цей репозиторій — **рівень 1** (оцінка «3»). Рівні 2 і 3 виконуються у власному
наскрізному репозиторії `vtfk-sid` і здаються на захисті.

---

## Як почати

1. Натисни **Code → Codespaces → Create codespace on main**.
2. Зачекай, поки середовище збереться (перший раз — кілька хвилин).
3. Перевір, що Docker на місці:

   ```bash
   docker version
   ```

   Мають вивестися блоки `Client:` і `Server:` без помилок з'єднання з демоном.

Коли здаси роботу — **видали простір**: `https://github.com/codespaces` → `…` → **Delete**.
Сховище витрачає твою квоту, доки простір існує, навіть зупинений.

---

## Що треба здати

Один файл — **`level1.sh`** у корені цього репозиторію. Його пишеш ти; у шаблоні його немає
навмисно.

### Контракт

Скрипт запускається **без аргументів** і має:

1. Починатися з `#!/usr/bin/env bash` і `set -euo pipefail`.
2. Підняти контейнер з іменем **`vtfk-lab01`** з образу **`ubuntu:24.04`** і **лишити його
   працювати** після завершення скрипту.
3. Записати значення змінної оточення `$VTFK_NONCE` у файл **`/tmp/vtfk-nonce`
   всередині контейнера**. Змінну передає перевірка; щоразу вона інша.
4. Надрукувати в стандартний вивід рівно такі рядки (порядок вільний, інший вивід дозволено):

   ```
   CONTAINER_PID=<PID головного процесу всередині контейнера>
   CONTAINER_PROCS=<скільки процесів видно всередині>
   HOST_PROCS=<скільки процесів видно на хості>
   ```

5. Завершитися кодом `0`.
6. **Бути ідемпотентним**: повторний запуск без ручного прибирання не повинен падати через
   те, що контейнер із таким іменем уже існує.
7. Не вимагати інтерактивного вводу — жодних питань «yes/no» без автопідтвердження.

Не забудь зробити файл виконуваним:

```bash
chmod +x level1.sh
git add level1.sh && git commit -m "ЛР1 рівень 1" && git push
```

## Як здати

Здача — **тег**, не просто пуш. Пуші безкоштовні й нічого не запускають; перевірка
стартує на тезі `submit/*`:

```bash
git tag submit/lab01
git push --tags
```

Результат з'явиться у вкладці **Actions** цього репозиторію й у релізі за тегом. Кожна
перевірка звітує окремо, тож видно, що саме не зійшлося.

**Повторна здача — переставленням того самого тега**, а не новим:

```bash
git tag -f submit/lab01
git push -f --tags
```

Це нормальний і передбачений шлях: перший тег означав «здаю», новий — «здаю кращу
версію». Кількість спроб не обмежена, доки відкритий модуль. Тег на лабораторну
**один** — `submit/lab01`; нумерованих на кшталт `submit/lab01-2` у цьому курсі немає.

## Що перевіряється

| # | Перевірка |
|---|---|
| 1 | `level1.sh` існує і виконуваний |
| 2 | завершується кодом `0` |
| 3 | контейнер `vtfk-lab01` працює й зібраний з `ubuntu:24.04` |
| 4 | `$VTFK_NONCE` лежить у `/tmp/vtfk-nonce` **всередині** контейнера |
| 5 | процесів усередині менше, ніж на хості |
| 6 | надруковані значення збігаються з тим, що виміряла перевірка |

Рівень 1 зараховується, **коли пройшли всі шість**.

Перевірка вимірює ізоляцію самостійно, через Docker, а не вірить виводу скрипта. Тому
скрипт, який просто друкує правильні числа, не пройде: `nonce` можна дістати лише з файлу
всередині справжнього контейнера.

---

## Підказки

- `docker run -d --name … ubuntu:24.04 sleep infinity` піднімає контейнер, який не завершується одразу.
- Передати змінну всередину: `docker exec -e VTFK_NONCE="$VTFK_NONCE" …`
- Порахувати процеси: `ls -d /proc/[0-9]* | wc -l` — працює і на хості, і в контейнері.
- PID головного процесу контейнера читається з `/proc/1/…` **зсередини** контейнера.
- Ідемпотентність найпростіше дає `docker rm -f <ім'я> >/dev/null 2>&1 || true` на початку.

Якщо `shellcheck` підкреслює щось у редакторі — це не помилка перевірки, але варто прочитати.
